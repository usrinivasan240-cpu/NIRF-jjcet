19. DEPARTMENT TARGETS DESIGN ASSESSMENT & RECOMMENDATION
================================================================================
Targets ARE implemented in a basic form but are too simple for proper NIRF:

Current Limitations:
- Only one numeric yearly and achieved per category per department per year
- No sub-metric breakdown (e.g., TLR has sub-metrics: FSR, FQR, ESP)
- No historical year-over-year comparison
- No linkage to actual data collections

Recommended Design:
  collection: "targets"
  {
    id: string,
    departmentId: string,
    academicYear: string,          // "2024-25"
    parameter: string,             // "TLR" | "RPC" | "GO" | "OI" | "PR"
    subMetric: string,             // "FSR" | "FQR" | "ESP" | "PU" | "PP"
    targetValue: number,
    achievedValue: number,
    unit: string,                  // "ratio" | "percentage" | "count"
    weight: number,                // NIRF weightage
    calculatedFrom: string,        // "auto" | "manual"
    sourceCollection: string,      // which collection to auto-calculate from
    status: string,
    createdAt: timestamp,
    updatedAt: timestamp
  }

21. HOW ACHIEVED VALUES SHOULD BE CALCULATIONS
================================================================================
Currently achieved is manually entered. They should be auto-calculated:
- Publications achieved = COUNT(publications WHERE deptId=X AND status='published')
- Patents achieved = COUNT(patents WHERE deptId=X AND status='granted')
- Research = COUNT(research WHERE deptId=X AND sanctionedYear=current)
- Events = COUNT(events WHERE deptId=X AND date IN currentYear)
- NIRF Scores = formula-based: TLR(30%), RPC(30%), GO(20%), OI(10%), PR(10%)

29. APPROVAL WORKFLOW
================================================================================
Levels: STAFF → HOD → VP → PRINCIPAL → LOCKED

Flow:
1. Staff creates report (status: DRAFT, currentLevel: STAFF)
2. Staff submits report (status: SUBMITTED)
3. Approval record created at STAFF level
4. STAFF approves → auto-creates HOD approval → currentLevel = HOD
5. HOD approves → auto-creates VP approval → currentLevel = VP
6. VP approves → auto-creates PRINCIPAL approval → currentLevel = PRINCIPAL
7. PRINCIPAL approves → status = LOCKED (final)
8. Reject at any level → report reverts to DRAFT
9. Locked reports cannot be edited or deleted

41. PROBLEMS IN CURRENT REPORT GENERATION MODULE
================================================================================

1. Client-side only — ALL Firestore data fetched in browser (N+1 queries)
2. No server-side API for NIRF calculation
3. NIRF formulas are simplistic — not aligned with actual NIRF methodology
4. No data caching — every generation re-fetches all collections
5. No PDF generation — relies on browser print dialog
6. Duplicate code — nirf-report and reports pages have ~400 lines duplicated
7. Hardcoded JJCET branding — college name, logo, address hardcoded
8. No data validation — Zod is installed but never used
9. Signatures are fake — hardcoded names, no digital signature integration
10. No report versioning — no audit trail of changes
11. Trend data is fabricated — historical scores are Math.max(total - X, Y)
12. No export to PDF/DOCX — only CSV export exists
13. ReportConfig not typed strictly — uses any extensively
14. Firestore rules are wide open — allow read, write: if true
